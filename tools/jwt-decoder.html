📖 详细使用教程

第一步：获取JWT Token

从您的应用程序、API响应、Cookie或其他数据源中获取完整的JWT Token。JWT Token通常由三部分组成，用点（.）分隔，形如：xxxxxx.yyyyyy.zzzzzz

第二步：粘贴Token

将获取到的JWT Token粘贴到输入框中。如果Token不完整（缺少任何一部分），解析结果可能不准确或报错。

第三步：解析Token

点击"解析JWT"按钮，系统会自动：

  • 将Token分解为Header、Payload、Signature三部分
  • 对Header和Payload进行Base64URL解码
  • 将Base64URL解码后的内容解析为JSON
  • 格式化JSON并显示在相应的面板中
第四步：查看结果

解析结果会显示在三个卡片中：

  • Header：显示Token的元数据（类型、算法等）
  • Payload：显示Token的声明（Claims，如用户ID、过期时间等）
  • Signature：显示Token的签名（用于验证完整性）
  • 格式化显示：将Header和Payload合并为完整的JSON并美化

💡 实际应用场景

API调试

在调试JWT认证的API时，解析返回的Token，快速查看Header中的算法和Payload中的用户信息，验证接口是否正常工作。

用户认证

验证JWT Token中的用户身份信息，检查Payload中的声明是否符合预期，确保用户认证的准确性。

Token验证

检查JWT Token的过期时间（exp声明）和生效时间（nbf声明），确保Token在有效期内，避免过期导致的认证失败。

系统集成

在集成第三方JWT认证系统时，解析对方提供的Token，理解其结构和数据格式，确保与自身系统的兼容性。

❓ 常见问题FAQ

A: JWT Token由三部分组成，用点（.）分隔：Header.Payload.Signature。
- Header：JSON对象，包含Token类型（typ，通常是"JWT"）和使用的哈希算法（alg，如HMAC SHA256、RSA等）
- Payload：JSON对象，包含声明（Claims），通常包括用户信息、过期时间等
- Signature：签名，用于验证Token的完整性和防止篡改

A: Base64URL是Base64的一种变体，特别适用于URL和文件名。主要区别在于：
- 将标准Base64中的+替换为-
- 将标准Base64中的/替换为_
- 省略填充字符=
JWT标准（RFC 7519）要求使用Base64URL编码，因为它对URL更加友好。

A: JWT本身并不存储密码，它只是一种数据格式。但JWT有一些需要注意的安全问题：
- JWT是明文的，Payload中的信息可以很容易被解码查看（只要有Token就能解析）
- 签名验证必须在服务器端进行，客户端无法验证Token的真实性
- 如果使用不对称算法（如RS256），需要确保私钥安全
- 如果使用对称算法（如HS256），需要确保密钥安全且不泄露

A: 验证JWT Token需要以下步骤：
1. 验证Token格式是否正确（三部分由点分隔）
2. 使用正确的算法和密钥验证签名
3. 检查Token是否过期（exp声明）
4. 检查Token生效时间（nbf声明）
5. 检查颁发者（iss声明）和受众（aud声明）是否符合预期
注意：仅解码JWT不能验证其有效性，必须通过密钥验证签名。

A: JWT和Session都是用户认证的方式，但有本质区别：

JWT（Token方式）：
- 无状态（Stateless）：服务器不需要存储Token
- 自包含（Self-contained）：Token本身包含所有认证信息
- 可扩展性好：适合微服务架构
- 可跨域使用：适合API认证

Session（会话方式）：
- 有状态（Stateful）：服务器需要存储会话信息
- 依赖Cookie：通常通过Cookie存储Session ID
- 可回收：服务器可以主动销毁会话
- 安全性依赖服务器：更容易防止CSRF等攻击

📚 JWT基础知识

JWT（JSON Web Token）是一种开放标准（RFC 7519），它定义了一种紧凑的、自包含的方式，用于在各方之间作为JSON对象安全地传输信息。JWT可以被签名（使用HMAC算法）或使用RSA或ECDSA的公钥/私钥对进行加密。

JWT的标准声明（Registered Claims）
声明 全称 描述 示例
iss Issuer Token颁发者 "https://example.com"
sub Subject Token主题（通常是用户ID） "1234567890"
aud Audience Token受众 "app1"
exp Expiration Time Token过期时间（Unix时间戳） 1516239022
nbf Not Before Token生效时间（Unix时间戳） 1516238722
iat Issued At Token颁发时间（Unix时间戳） 1516238022
jti JWT ID Token唯一标识符 "a1b2c3d4"
常见的JWT算法
算法 类型 描述 安全性
HS256 对称 HMAC + SHA-256 ✅ 密钥安全即可
HS384 对称 HMAC + SHA-384 ✅ 密钥安全即可
HS512 对称 HMAC + SHA-512 ✅ 密钥安全即可
RS256 非对称 RSA + SHA-256 ✅ 私钥安全即可
RS384 非对称 RSA + SHA-384 ✅ 私钥安全即可
RS512 非对称 RSA + SHA-512 ✅ 私钥安全即可
ES256 非对称 ECDSA + P-256 + SHA-256 ✅ 私钥安全即可
JWT的使用场景
  • 用户认证：最常见的用途，存储用户ID、角色等信息
  • 信息交换：在各方之间安全传输信息
  • API授权：用于API的访问授权和权限控制
  • 单点登录(SSO)：在多个系统间共享用户认证状态
  • 微服务通信：在微服务间传递用户信息和权限
JWT的优缺点
优点
  • 无状态：服务器不需要存储会话信息
  • 可扩展性：适合分布式系统和微服务架构
  • 安全：支持多种签名和加密算法
  • 灵活：可以自定义声明，满足不同需求
  • 轻量级：JSON格式，传输效率高
缺点
  • Token长度较长，URL传输时可能超长
  • Token一旦颁发，在过期前无法撤销
  • Payload信息是明文的，不可存储敏感数据
  • 需要处理Token过期和刷新机制

JWT结构解析

JWT（JSON Web Token）由三部分组成，用点（.）分隔：header.payload.signature

  • Header：包含Token类型和使用的哈希算法
  • Payload：包含声明（Claims），通常是用户信息和过期时间
  • Signature：用于验证Token的完整性
