Cron表达式语法

Cron表达式是一个字符串，由6或7个子表达式组成，描述任务的执行时间表。

字段 允许值 说明
秒 (Seconds) 0-59, * / , - 第几秒执行
分钟 (Minutes) 0-59, * / , - 第几分钟执行
小时 (Hours) 0-23, * / , - 第几小时执行
日期 (Day of Month) 1-31, * / , - ? L W 每月的第几天
月份 (Month) 1-12 or JAN-DEC, * / , - 第几月
周 (Day of Week) 1-7 or SUN-SAT, * / , - ? L # 周几 (1=周日, 2=周一...)
年 (Year) 1970-2099, * / , - 哪一年

特殊字符：* 表示所有值，? 表示无特殊值，- 表示范围，, 表示列举，/ 表示步长

常见例子

// 示例1: 每天凌晨1点执行 秒: 0 分钟: 0 小时: 1 日期: * 月份: * 周: ? 结果: 0 0 1 * * ? // 示例2: 每周一到周五的上午9点执行 秒: 0 分钟: 0 小时: 9 日期: * 月份: * 周: 1-5 结果: 0 0 9 * * 1-5 // 示例3: 每5分钟执行一次 秒: 0 分钟: */5 小时: * 日期: * 月份: * 周: ? 结果: 0 */5 * * * ? // 示例4: 每月1号和15号的 midnight 执行 秒: 0 分钟: 0 小时: 0 日期: 1,15 月份: * 周: ? 结果: 0 0 0 1,15 * ?

应用场景
Cron表达式在不同领域的应用
系统运维

在Linux服务器上配置定时任务，如数据库备份、日志清理、系统监控等。Linux Cron是最早支持Cron表达式的系统之一。

例子：每天凌晨2点备份数据库：0 2 * * * /usr/bin/mysqldump
Java开发

Spring框架和Quartz调度器广泛使用Cron表达式来配置定时任务、批处理作业、数据同步等功能。

例子：每周一上午10点执行数据同步：0 0 10 ? * MON
数据处理

定期执行数据分析、报表生成、缓存更新等任务，确保数据的及时性和准确性。

例子：每小时更新一次数据缓存：0 0 * * * *
云服务部署

在Kubernetes、Docker等容器化环境中配置定时任务，如定期重启服务、资源清理、健康检查等。

例子：每天定时重启应用：0 0 3 * * ?
邮件通知

定期发送邮件通知、报表邮件、提醒邮件等，保持用户和系统的及时沟通。

例子：每周五下午5点发送周报：0 0 17 ? * FRI
监控告警

配置系统监控、性能检查、异常告警等定时任务，确保系统的稳定运行。

例子：每5分钟检查一次系统状态：0 */5 * * * ?
⚠️ 注意： 在生产环境中配置Cron表达式时，请确保充分测试，避免因为表达式配置错误导致任务无法按时执行或频繁执行。
常见问题解答

* 表示匹配该字段的所有可能值，例如在分钟字段使用 * 表示每分钟都执行。而 ? 表示不指定具体值，通常用于日期和周字段中，表示不关心是本月的第几天还是星期几。在Spring Cron中，日期和周字段必须有一个是 ?。

可能有以下几个原因：1) 表达式语法错误，可以使用我们的工具验证；2) 调度器服务未启动；3) 表达式配置的时间点还未到达；4) 系统时间不正确；5) 任务配置有误。建议先使用我们的工具生成并验证表达式，然后检查调度器日志。

主要区别：1) 字段数量：Spring Cron有6位（秒 分 时 日 月 周），Linux Cron通常是5位（分 时 日 月 周）；2) 周字段：Spring的周字段1=周日，Linux的周字段0=周日；3) 特殊符号：Spring支持更多特殊符号如L（最后）、W（工作日）等；4) 年字段：Spring Cron支持可选的年字段。

在Spring Cron中，可以在日期字段使用 L 来表示每月的最后一天。例如：0 0 0 L * ? 表示每月最后一天的0点执行。需要注意的是，L只能用在日期字段，并且当日期字段使用L时，周字段必须使用 ?。

您可以使用我们的Cron表达式生成器工具来验证。输入您的表达式，工具会显示接下来的5次执行时间。您可以对比这些时间是否符合您的预期。此外，也可以使用一些在线的Cron表达式验证工具，或者在开发环境中进行实际测试。

步长使用 / 符号表示。例如 */5 表示每5个单位执行一次。在分钟字段，*/5 表示0、5、10、15、...、55分钟；在小时字段，*/2 表示0、2、4、...、22点。步长可以与范围结合使用，如 1-10/2 表示在1到10之间，每2个单位执行一次。

4. Cron表达式最佳实践
  • 避免频繁执行：合理设置执行频率，避免过于频繁的任务调度影响系统性能
  • 处理时区：明确任务执行的时区，考虑服务器时区与业务时区的一致性
  • 错误处理：为定时任务配置完善的错误处理和重试机制
  • 日志记录：详细记录任务执行日志，便于问题追踪和排查
  • 监控告警：建立任务执行监控，对于失败的任务及时告警
  • 并发控制：考虑任务并发执行的情况，避免资源竞争
  • 分布式部署：在分布式环境中，确保定时任务只在一个节点上执行
