📚 第一部分：HTTP状态码基础

1.1 什么是HTTP状态码？

HTTP状态码（HTTP Status Code）是3位数字的代码，用于表示HTTP请求的处理结果。它位于HTTP响应的第一行，格式如下：

HTTP响应示例 
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 1024

{
  "status": "success",
  "data": { ... }
}

HTTP/1.1 404 Not Found
Content-Type: application/json

{
  "error": "Resource not found"
}

HTTP/1.1 500 Internal Server Error
Content-Type: text/html

<html>
  <body>服务器内部错误</body>
</html>

1.2 状态码格式

HTTP状态码由3位数字组成，第一位数字表示类别，后两位表示具体状态：

状态码分类
类别范围含义描述
1xx100-199Informational信息，请求已接收，继续处理
2xx200-299Success成功，请求已成功处理
3xx300-399Redirection重定向，需要进一步操作完成请求
4xx400-499Client Error客户端错误，请求包含语法错误或无法完成
5xx500-599Server Error服务器错误，服务器处理请求时发生错误

1.3 HTTP响应结构

一个完整的HTTP响应包含：

HTTP响应结构 
HTTP/1.1 200 OK                     ← 状态行 (Status Line)
Server: nginx/1.18.0                ← 响应头 (Response Headers)
Date: Mon, 17 Sep 2025 10:00:00 GMT
Content-Type: application/json
Content-Length: 1024
Cache-Control: max-age=3600
                                  ← 空行
{                               ← 响应体 (Response Body)
  "status": "success",
  "data": { ... }
}

📋 第二部分：详细状态码列表

2.1 1xx - 信息性状态码 (Informational)

表示请求已接收，继续处理。这些状态码是临时响应，通常用于WebSocket或HTTP/2等协议：

1xx状态码
状态码名称含义
100Continue服务器已接收请求头，客户端应继续发送请求体
101Switching Protocols服务器切换协议，如从HTTP升级到WebSocket
102Processing服务器已接收请求，但尚未完成处理
103Early Hints服务器在最终响应前返回的一些提示信息

2.2 2xx - 成功状态码 (Success)

表示请求已成功接收、理解并接受。这是最常见的状态码类别：

2xx状态码
状态码名称含义常见用法
200OK请求成功GET、POST等请求的成功响应
201Created请求成功，资源已创建POST创建资源后返回
202Accepted请求已接收，但尚未处理完成异步处理任务
204No Content请求成功，但响应体为空DELETE操作等
205Reset Content请求成功，要求客户端重置文档视图表单重置
206Partial Content服务器成功处理了部分GET请求分段下载、Range请求
最常用的成功状态码：200, 201, 204

2.3 3xx - 重定向状态码 (Redirection)

表示需要客户端采取进一步操作才能完成请求。通常用于URL重定向：

3xx状态码
状态码名称含义处理方式
300Multiple Choices多个选择，客户端可选择一个资源显示选择列表
301Moved Permanently资源永久移动到新位置客户端应更新链接
302Found资源临时移动到新位置客户端可继续使用旧链接
303See Other重定向到其他URI，应使用GET方法POST后重定向到GET
304Not Modified资源未修改，可使用缓存版本缓存有效性检查
307Temporary Redirect资源临时重定向，应保持请求方法类似302，但保持方法
308Permanent Redirect资源永久重定向，应保持请求方法类似301，但保持方法
注意：301和302的区别：301是永久重定向（浏览器会缓存），302是临时重定向（浏览器不会缓存）

2.4 4xx - 客户端错误状态码 (Client Error)

表示客户端发送的请求有错误，服务器无法处理。这是开发中最常遇到的错误类别：

4xx状态码
状态码名称含义常见原因
400Bad Request请求语法错误参数缺失、格式错误等
401Unauthorized请求需要身份验证未提供或无效的认证凭证
403Forbidden服务器拒绝请求无权限访问资源
404Not Found资源不存在URL错误、资源已删除等
405Method Not Allowed请求方法不被允许使用了不支持的HTTP方法
406Not Acceptable请求的内容类型不被支持Accept头不匹配
408Request Timeout请求超时服务器等待请求时间过长
409Conflict请求与当前资源状态冲突并发修改冲突
410Gone资源已永久删除资源不再可用
413Payload Too Large请求体过大超过了服务器限制
414URI Too LongURI过长超过了服务器URI长度限制
415Unsupported Media Type不支持的媒体类型Content-Type不被支持
422Unprocessable Entity请求体格式正确但语义错误数据验证失败
429Too Many Requests请求过多，限流API限流
最常用的客户端错误：400, 401, 403, 404

2.5 5xx - 服务器错误状态码 (Server Error)

表示服务器在处理请求时发生错误。这些错误通常需要服务器端的开发人员来解决：

5xx状态码
状态码名称含义常见原因
500Internal Server Error服务器内部错误代码异常、配置错误等
501Not Implemented服务器不支持请求的功能未实现的功能
502Bad Gateway网关错误，上游服务器响应无效代理服务器问题
503Service Unavailable服务器暂时不可用服务器过载、维护中
504Gateway Timeout网关超时上游服务器响应超时
505HTTP Version Not Supported不支持的HTTP版本服务器不支持请求的HTTP版本
最常用的服务器错误：500, 502, 503, 504

3.3 错误处理最佳实践

错误处理建议
  1. 使用正确的状态码：根据错误的实际原因选择合适的状态码
  2. 提供详细的错误信息：错误响应中应包含错误码、错误消息和详细信息
  3. 保持响应格式一致：成功和错误响应应使用相同的格式结构
  4. 不要泄露敏感信息：生产环境中不要在错误响应中返回调用栈或敏感数据
  5. 使用标准的错误码：为常见的错误类型定义标准的错误码
  6. 支持多种格式：根据Accept头返回JSON或XML格式的错误信息
  7. 记录错误日志：服务器端应记录详细的错误日志用于调试
  8. 提供请求ID：在响应中包含请求ID，方便用户引用错误

5.1 JavaScript中处理HTTP状态码

Fetch API状态码处理 
// 使用Fetch API处理不同的HTTP状态码
async function fetchUser(userId) {
  try {
    const response = await fetch(`/api/users/${userId}`);
    
    // 检查响应是否成功
    if (!response.ok) {
      // 根据不同的状态码处理不同的错误
      switch (response.status) {
        case 401:
          throw new Error('请登录后重试');
        case 403:
          throw new Error('您没有权限访问此资源');
        case 404:
          throw new Error('用户未找到');
        case 429:
          const retryAfter = response.headers.get('Retry-After');
          throw new Error(`请求过多，请${retryAfter}秒后重试`);
        case 500:
        case 503:
          throw new Error('服务器错误，请稍后重试');
        default:
          throw new Error(`请求失败: ${response.status}`);
      }
    }
    
    const data = await response.json();
    return data;
    
  } catch (error) {
    console.error('请求失败:', error.message);
    // 显示错误信息给用户
    showErrorMessage(error.message);
    return null;
  }
}

// 更通用的HTTP请求封装
class HttpClient {
  constructor(baseUrl = '') {
    this.baseUrl = baseUrl;
  }
  
  async request(method, path, body = null, headers = {}) {
    const url = this.baseUrl + path;
    const options = {
      method,
      headers: { 'Content-Type': 'application/json', ...headers }
    };
    
    if (body) {
      options.body = JSON.stringify(body);
    }
    
    const response = await fetch(url, options);
    
    // 处理响应
    if (response.status >= 200 && response.status < 300) {
      // 成功响应
      if (response.status === 204) {
        return { success: true, data: null };
      }
      const data = await response.json();
      return { success: true, data };
    }
    
    // 错误响应
    let errorData;
    try {
      errorData = await response.json();
    } catch (e) {
      errorData = { message: '服务器错误' };
    }
    
    return {
      success: false,
      status: response.status,
      error: errorData
    };
  }
  
  // 方便方法
  async get(path, headers) {
    return this.request('GET', path, null, headers);
  }
  
  async post(path, body, headers) {
    return this.request('POST', path, body, headers);
  }
  
  async put(path, body, headers) {
    return this.request('PUT', path, body, headers);
  }
  
  async delete(path, headers) {
    return this.request('DELETE', path, null, headers);
  }
}

// 使用示例
const client = new HttpClient('https://api.example.com');

// 获取用户
const { success, data, error } = await client.get('/users/123');
if (success) {
  console.log('用户数据:', data);
} else {
  console.error('错误:', error);
}

// 创建用户
const result = await client.post('/users', {
  name: 'John Doe',
  email: 'john@example.com'
});

// 使用axios库
const axios = require('axios');

async function fetchWithAxios() {
  try {
    const response = await axios.get('/api/users/123');
    return response.data;
  } catch (error) {
    if (error.response) {
      // 服务器响应了错误状态码
      console.error('状态码:', error.response.status);
      console.error('错误数据:', error.response.data);
    } else if (error.request) {
      // 请求已发送但未收到响应
      console.error('请求超时');
    } else {
      // 请求发送前发生错误
      console.error('请求配置错误:', error.message);
    }
  }
}

Express.js状态码监控中间件 
// 状态码统计中间件
const statusCodes = {};

function statusCodeMonitor(req, res, next) {
  const start = Date.now();
  
  // 监听响应完成事件
  res.on('finish', () => {
    const statusCode = res.statusCode;
    const duration = Date.now() - start;
    
    // 统计状态码
    if (!statusCodes[statusCode]) {
      statusCodes[statusCode] = { count: 0, totalDuration: 0 };
    }
    statusCodes[statusCode].count++;
    statusCodes[statusCode].totalDuration += duration;
    
    // 计算平均响应时间
    const avgDuration = statusCodes[statusCode].totalDuration / statusCodes[statusCode].count;
    
    // 记录日志（可以改为存储到数据库）
    console.log(`[${new Date().toISOString()}] ${req.method} ${req.originalUrl} ` +
                `${statusCode} ${duration}ms`);
    
    // 如果是错误状态码，发送告警
    if (statusCode >= 400) {
      sendAlert(`错误状态码: ${statusCode}`, {
        method: req.method,
        url: req.originalUrl,
        statusCode,
        duration
      });
    }
  });
  
  next();
}

// 定期输出状态码统计
function logStatusCodes() {
  console.log('\n=== 状态码统计 ===');
  Object.entries(statusCodes).forEach(([code, stats]) => {
    console.log(`状态码 ${code}: ${stats.count} 次, 平均响应时间: ${stats.totalDuration / stats.count}ms`);
  });
  console.log('===================\n');
}

// 每5分钟输出一次统计
setInterval(logStatusCodes, 5 * 60 * 1000);

// 使用中间件
app.use(statusCodeMonitor);

// 获取状态码统计API
app.get('/api/stats/status-codes', (req, res) => {
  res.json(statusCodes);
});

  • 改善用户体验：为用户提供清晰的错误信息和处理建议
  • 简化调试：状态码可以快速定位问题的来源和类型
  • 增强安全性：通过状态码可以检测和防范各种攻击
  • 优化性能：通过监控状态码可以发现性能瓶颈
