📚 第一部分：代码格式化基础

1.1 什么是代码格式化？

代码格式化涉及以下几个方面：

代码格式化包含的内容
  • 缩进（Indentation）：代码的层次结构通过空格或制表符表示
  • 空格（Spacing）：在关键字、运算符、括号等周围添加适当的空格
  • 换行（Line Breaks）：在适当的位置换行，保持代码的可读性
  • 括号样式（Bracket Style）：大括号、方括号、圆括号的放置方式
  • 引号样式（Quote Style）：使用单引号还是双引号
  • 分号（Semicolons）：是否在语句末尾添加分号

1.2 为什么代码格式化很重要？

代码格式化的价值
价值维度具体体现影响
可读性一致的格式使代码更容易阅读和理解减少理解代码的时间
可维护性规范的格式使代码修改和扩展更容易降低维护成本
协作效率团队成员使用相同的代码风格减少代码审查中的风格相关讨论
代码质量格式化过程中可以检测到一些潜在问题提升整体代码质量

1.3 格式化 vs 代码检查

格式化 vs 代码检查
方面代码格式化代码检查
目标统一代码风格检测代码问题和潜在错误
处理方式自动修改代码格式报告问题但不自动修复
工具Prettier、Beautifier等ESLint、JSHint等

🛠️ 第二部分：常见代码格式化工具

2.1 Prettier

Prettier是目前最流行的代码格式化工具之一，支持多种编程语言：

Prettier特性
  • 意见化（Opinionated）：有明确的默认配置，减少团队讨论
  • 支持多语言：JavaScript、TypeScript、CSS、SCSS、Less、HTML、JSON、GraphQL、Markdown等
  • 可配置性强：可以自定义缩进、引号、换行等规则
  • 集成性好：可以与大多数编辑器和IDE集成
  • 快速：高性能的格式化引擎
Prettier安装与配置 
# 使用npm安装
npm install --save-dev --save-exact prettier

# .prettierrc配置文件
{
  "semi": true,
  "trailingComma": "es5",
  "singleQuote": false,
  "printWidth": 80,
  "tabWidth": 2,
  "useTabs": false,
  "bracketSpacing": true
}

2.2 ESLint

ESLint是一个可配置的JavaScript代码检查工具，也支持代码格式化：

ESLint特性
  • 完全可配置：可以自定义任何规则
  • 插件化架构：支持通过插件扩展功能
  • 支持最新语法：支持ES2025+、JSX、TypeScript等
  • 自动修复：可以自动修复部分代码问题
ESLint安装与使用 
# 使用npm安装
npm install eslint --save-dev

# 初始化配置文件
npx eslint --init

# 运行ESLint检查
npx eslint src/**/*.js

# 修复可自动修复的问题
npx eslint --fix src/**/*.js

👥 第三部分：团队协作与代码格式化

3.1 团队代码格式化规范

在团队协作中，统一的代码格式化规范至关重要：

团队规范建立步骤
  1. 选择工具：选择一个适合项目的代码格式化工具（推荐Prettier）
  2. 确定配置：团队讨论并确定统一的配置方案
  3. 创建配置文件：在项目根目录创建配置文件并提交到版本控制
  4. 集成到工作流：将格式化工具集成到编辑器、构建流程和CI/CD中
  5. 自动执行：设置pre-commit hook自动格式化代码

3.2 Pre-commit Hooks

使用Git的pre-commit钩子自动格式化代码：

Husky + lint-staged配置 
# 1. 安装Husky
npm install husky --save-dev
npx husky install

# 2. 添加pre-commit钩子
npx husky add .husky/pre-commit "npx lint-staged"

# 3. 安装lint-staged
npm install lint-staged --save-dev
.lintstagedrc配置 
{
  "*.{js,jsx,ts,tsx}": [
    "prettier --write",
    "eslint --fix"
  ],
  "*.{css,scss,less}": ["prettier --write"],
  "*.{html,json,md}": ["prettier --write"]
}

3.3 编辑器集成

VS Code集成
  • 安装扩展：Prettier - Code formatter、ESLint
  • 配置设置：设置默认格式化工具为Prettier，启用格式化于保存
VS Code settings.json 
{
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true,
  "editor.formatOnPaste": true,
  "prettier.printWidth": 80,
  "prettier.tabWidth": 2,
  "prettier.useTabs": false,
  "prettier.semi": true,
  "prettier.singleQuote": false
}

💻 第四部分：编程语言代码格式化实战

4.1 JavaScript代码格式化

JavaScript格式化示例 
// 未格式化的代码
function add(a,b){return a+b;}
const obj={name:'John',age:30,city:'New York'};
if(condition){console.log('yes');}else{console.log('no');}

// 格式化后的代码
function add(a, b) {
  return a + b;
}

const obj = {
  name: 'John',
  age: 30,
  city: 'New York'
};

if (condition) {
  console.log('yes');
} else {
  console.log('no');
}

// 使用Prettier格式化
const prettier = require('prettier');
const code = "function add(a,b){return a+b;}";
const formatted = prettier.format(code, {
  parser: 'babel',
  singleQuote: true,
  semi: true,
  tabWidth: 2
});

console.log(formatted);

4.2 CSS代码格式化

CSS格式化示例 
/* 未格式化的CSS */
body{margin:0;padding:0;font-family:Arial,sans-serif;}
.container{width:1200px;margin:0 auto;}

/* 格式化后的CSS */
body {
  margin: 0;
  padding: 0;
  font-family: Arial, sans-serif;
}

.container {
  width: 1200px;
  margin: 0 auto;
}

4.3 HTML代码格式化

HTML格式化示例 
<!-- 未格式化的HTML -->
<div class="container"><h1>Hello</h1><p>World</p></div>

<!-- 格式化后的HTML -->
<div class="container">
  <h1>Hello</h1>
  <p>World</p>
</div>

⚡ 第五部分：代码格式化性能优化

5.1 性能优化技巧

性能优化建议
  • 只格式化修改的文件：使用lint-staged或类似工具，只格式化git暂存区的文件
  • 避免格式化node_modules：在配置文件中排除node_modules目录
  • 使用缓存：启用ESLint的缓存功能
  • 并行处理：使用并行工具（如lint-staged）提高格式化速度
  • 限制文件大小：对于特别大的文件，考虑手动格式化

🎯 第六部分：代码格式化最佳实践

6.1 通用最佳实践

通用建议
  • 保持一致：整个代码库使用相同的格式化规则
  • 自动化：尽可能自动化格式化过程，减少人工干预
  • 版本控制：将格式化配置文件提交到版本控制
  • 团队协商：在团队中协商确定格式化规则，避免个人偏好影响
  • 定期更新：定期更新格式化工具到最新版本
  • 文档化：将格式化规则文档化，方便新成员理解

🎯 总结

代码格式化是现代软件开发的重要环节，它不仅影响代码的外观，更重要的是影响代码的可读性、可维护性和团队协作效率。通过使用合适的格式化工具和规范，你可以显著提升开发体验和代码质量。

关键要点：

  • 代码格式化和代码检查是两个不同的概念，但可以结合使用
  • 选择适合你项目的格式化工具（推荐Prettier）
  • 在团队中建立统一的格式化规范
  • 自动化格式化过程，减少人工干预
  • 将格式化工具集成到编辑器、构建流程和CI/CD中
